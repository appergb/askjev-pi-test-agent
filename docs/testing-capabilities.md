# 当前完成度与测试技能

核查日期：**2026-09-25**。版本：**askJEV Agent 1.5.0，工程试用版**。本次核对公开主分支 `c663820` 对应的运行代码、本机安装、技能加载记录和真实测试结果。脱敏数据见[本次验收摘要](evidence/capability-review-2026-09-25.json)。

**已经能对指定 JavaScript 模块和本地静态页面生成、执行测试，交付失败证据，并用原测试验证修复。** 它有专门的测试技能，也有实际执行器；目前还需要明确的任务文件、源码范围和需求。不能把这个完成度解释为任意项目自动接入或可靠的整体代码评分。

## 已实现到什么程度

| 部分 | 当前可用能力 | 主要边界 |
| --- | --- | --- |
| 终端前端 | `askjev-cli` 品牌界面、对话、进度、报告、取消；固定默认模型 | 运行已有任务文件；无独立网页管理界面；终端对话仅在当前进程保留 |
| 测试后端 | 校验范围和预算、保存快照、运行原基线、调用模型、生成测试、隔离执行、保存证据 | 本机 macOS；批准的 JS 文件与本地静态页面；不能直接测试任意线上网站或后端 API |
| Node 测试 | Pi 写 `node:test`；读取实际断言与输出；支持明确配置的 `node:test` / `uvu` 原基线 | 需指定文件和依赖范围；不自动识别整个仓库的构建和测试环境 |
| 浏览器测试 | Chrome 执行点击、输入、选择、勾选及 DOM 断言；失败可保存截图 | 受限静态快照、每例新页面状态；截图是失败证据，不是视觉差异评分 |
| 多轮与后台 | `campaign` 有预算地补查、重复失败；`session` 后台运行、持久对话、取消和重开 | 不保证覆盖完整；重开不是崩溃后的步骤续跑；无金额上限或定时服务 |
| 评分与选测 | JEV 每批评一次支持度；默认全测；显式数值选测、冻结重放、评分诊断和故障降级 | 分数未校准；高分仍可能失败，低分也可能通过；无双轮独立评估 |
| 缺陷交接与回归 | `handoff` 交付需求和证据；`regress` 执行字节不变的原测试；`feedback` 记录结果 | 业务修复由编码 Agent 完成；断言是否合理、失败是否同一根因仍需审查 |

结构与源码职责见[当前框架](framework.md)。这里的“后端”主要指本机测试运行时；生成、JEV 评分和可选云端代理是独立组件，不能因本地检查通过就声称云服务已长期稳定。

## 五个内置测试技能

| 技能 | 负责的工作 | 使用范围与输出 |
| --- | --- | --- |
| [brainstorming](../skills/pi/brainstorming/SKILL.md) | 从需求和源码提出正常、边界、非法输入、重复操作等检查场景 | Node 与浏览器；给出有需求依据的候选，不虚构未定义的行为 |
| [ask-jev](../skills/pi/ask-jev/SKILL.md) | 整理场景、预期、需求引用与源码引用，调用实际 `askJEV` 工具 | Node 与浏览器；一批场景的支持度及执行选择；不凭分数认定 bug |
| [writing-tests](../skills/pi/writing-tests/SKILL.md) | 将候选写成测试、通过工具执行；仅修复生成测试的语法、导入或初始化错误 | Node 使用 `node:test`；浏览器转用下项的 JSON 格式；不能改业务代码或放宽失败断言 |
| [browser-tests](../skills/pi/browser-tests/SKILL.md) | 写受限浏览器操作和断言计划 | 只在浏览器任务追加；保存全部候选计划，仅执行选中项；单例最多 30 步 |
| [bugs](../skills/pi/bugs/SKILL.md) | 结合实际执行结果和需求分析问题，形成报告 | 区分业务断言失败、生成测试错误、环境错误和通过；证据来自执行器 |

这些技能是约束模型如何工作的指引，不是五个独立模型。执行权限、预算、快照保护和证据校验由程序实现，不能只靠技能文字保证。

加载机制可以在 [runner.mjs](../src/runner.mjs) 查到：运行时读取批准的技能正文，加入专用 Pi 系统提示，并在每次运行的 `manifest.json` 保存名称、路径与 SHA-256。Node 任务加载四个通用技能；浏览器任务再加载 `browser-tests`。本次两次真实运行的 manifest 分别确认了 **4 个和 5 个**技能。

[model.mjs](../src/model.mjs) 关闭 Pi 的个人技能、扩展和上下文自动发现，再使用上述批准内容。因此本机原生 Pi 中的其他技能不会自动混入 askJEV 测试。内部五个技能随 askJEV 安装，无需逐个安装。

## 现在怎么使用

人在终端输入 `askjev-cli`，再输入 `/run /absolute/path/to/task.json`。也可在本仓库根目录使用下面的脚本入口；前端样例自带选测设置，因此示例显式覆盖为全测：

```bash
askjev doctor --browser --probe --model flash-direct
askjev run --request examples/retry-demo/task.json --select all
askjev run --request examples/frontend-shop/task.json --select all
```

通过 Skill 调用时，优先使用已安装 `askjev-agent` 目录中的 `scripts/askjev.mjs` 代替裸命令。仅当私密配置定义了需要的 SSH 转发时，使用 `askjev connect start` 恢复连接。

发现问题后按 `handoff → 编码 Agent 核对并修复 → regress → feedback` 完成闭环；运行目录读取结果中的 `artifacts.directory`。多轮任务和后台任务的具体用法见 [campaign](campaigns.md)、[session](sessions.md)。评分故障默认阻塞，显式 `--scoring-failure all` 才能在全测时继续；这类结果必须注明没有完成真实评分。
