# Pi 测试智能体 1.0 MVP

2026-09-21，根据需求规格 v0.1 和用户本轮补充收敛。先验证已有云端 Open JEV 与生成模型，再完成本地真实闭环；模型无需重新部署。

原始[需求规格 v0.1](requirements-v0.1.md)作为评审资料归档；本文件记录本次 MVP 的实际选择，原稿中的待确认项不视为已实施事实。

## 已选范围

- 本地 Node.js CLI，嵌入固定版本 Pi 0.85.1 SDK；本项目实现专用运行时、工具、状态约束和报告，不使用个人 Pi 全局扩展。
- `askJEV` 连接现有 Open JEV。Pi 负责语义整理、检查项和测试代码，Codex 负责业务实现与修复。
- 本地 macOS Seatbelt 隔离执行无依赖 Node.js ESM 测试，禁止网络、子进程与业务源码写入，按白名单读取运行库和快照。其他系统先返回明确不支持。
- 首个样例为任务创建、幂等重试和数量边界；通过带缺陷版本、修复版本和原测试回归证明链路。
- CLI 提供 doctor、run、regress；Skills 分为 Pi 的评分、场景、测试、缺陷分析和 Codex 的调用检测。
- 每次保存代码快照、逐项评分、Pi 生成的测试、真实执行日志、结果、报告和版本清单。

## 评分契约

Open JEV 实际接口为 `POST /decide`，输入 `state` 和 `questions`，输出候选条件分布。固定候选集合为 supported / violated / unknown，读取 supported 的条件概率作为实验性排序信号，低分优先。unknown 获胜时保留 needs_context，不伪装为零分。该信号未经校准，不称为代码正确率或缺陷发生率；跨问题可比较性是本次评估对象，不是已验证事实。

基础检查始终保留。真实执行结果决定缺陷证据，分数不直接决定缺陷是否成立。首轮全部检查项执行，排序效果先观察，不据小样例宣称提升总体检出率。

## 验收

1. 云端状态、评分接口、生成模型真实工具调用通过。
2. 比较生成模型完成同一小任务的速度和有效工具参数，不只比较极短对话。
3. Pi 自主读取需求与源码、准备检查项、调用 askJEV、编写和执行测试。
4. 已知缺陷产生真实断言失败和可复现证据；修复后原测试不变且回归通过。
5. 超时、无效评分、错误 ID、环境失败和测试错误不能冒充产品缺陷；取消与预算有界。
6. 快照包含未提交内容，原业务文件不变，敏感配置不进入模型上下文和报告。

完整 v0.1 是后续产品规格。MVP 不宣称已覆盖任意框架、跨平台容器、多入口、生产远程权限管理或总体效果评估。
